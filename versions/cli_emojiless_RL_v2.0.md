cli_emojiless_RL_v2.0  (2026-09-11)

第一个可以正式拿来训练的版本：训练核心（损失 / 优化器 / 步长 / 数据）整个重做，
每一项都用对照实验确认过。v1.4 那套「逐 token 排名奖励 + AdamW」全部废弃。

基座：Qwen3-0.6B-Base（同流程对比后确认优于 chat 版），主干 fp16 冻结 + lm_head fp32 可训。

v1.4 -> v2.0 增量

  1. 损失：奖励式 -> 纯交叉熵
     - 旧：损失打在「模型自己提出的候选」上（字符级部分匹配 × 排名阶梯 100%…5%）
     - 新：loss = -log p(真值 token)，每个非标点位置各自一步
     - 对照（1000 字 / 423 步 / 同起点同 lr）：训练文本命中率
         候选+正挂 66.4% | 候选+倒挂 68.0% | 真值+正挂 83.4% | 真值+倒挂 82.2% | 真值+无权重 81.8%
       决定因素只有「损失打在谁身上」；排名阶梯的方向在噪声以内，故整个删除
  2. 优化器：AdamW -> 普通 SGD
     - AdamW 逐参数归一化：奖励整体乘常数完全不影响更新，20 倍奖励差被压平，
       「按质量分配力度」这条设计失效；且每步接近满步长，12799 步后把头磨坏
       （留出 top5 48.1% -> 22.9%，前 20 词表 1253 -> 848，标点平均排名 1.2 -> 153）
     - SGD 实测步长严格正比于权重：1.00/0.95/0.50/0.05 -> 1.0000/0.9500/0.5000/0.0500
  3. 步长：lr 3e-5 -> 1e-5，梯度裁剪关闭
     - 极化（前20累计概率）随 lr 单调（1 万字 / 5313 步，留出文本）：
         5e-4 +0.173 | 1e-4 +0.047 | 3e-5 +0.013 | 1e-5 -0.000 | 3e-6 -0.004
       到 1e-5 极化完全消失；5e-4 属于过冲（收益反而比 1e-4 小）
     - 裁剪按范数归一化，会把 rank-1 与 rank-20 的步长拉平，必须关
  4. 混料：打字 : 小说 = 25 : 75
     - 打字池 = 在线 accept + 离线 commit，按 (ctx, 文本) 去重合并
     - 同剂量对照（3000 步 / lr 1e-5，打字评估集从未参与训练）：
         打字占比 0%  -> 小说留出 72.4%  打字 top1 11.0%
         打字占比 25% -> 小说留出 72.0%  打字 top1 19.0%
         打字占比 50% -> 小说留出 71.9%  打字 top1 20.0%
         打字占比 100%-> 小说留出 69.2%  打字 top1 20.0%
       混料在小说侧几乎免费，打字侧把「掉 3.5 点」翻成「涨 4.5 点」
  5. 新增 tools/LlamaTreeExp/train_mix.py
     - 混料训练器：小说文本 + 打字池按比例逐步交替取样，收尾按五槽稀释方案落盘
  6. 清理
     - 删除早期原型与一次性脚本：tree_exp / tree_watcher / tree_watcher_v02 /
       tree_inprocess / ctypes_tree / bench_quant / rl_min_validate / eight_bit_adam
       及只服务它们的启动脚本（start-tree-* / start-exp-v0.2 / start-engine）
     - 删除死函数与死参数：rank_reward_path、unified_pipeline.main、
       unified_watcher.main、miss_weight、--rank-reward、--miss-weight
       （offline_train 的 --mode tree 分支仍在用 miss_weight，保留）
     - 清理无用 import 与只被已删代码使用的常量
  7. 落盘纪律
     - 只有实时槽（t0）会被强制写入；离线训练不再把五个稀释槽一起盖掉
  8. 验收口径
     - 三个指标：前20累计概率（极化探针）/ 命中率与脱靶率 / 最长链
     - 实现见 probe_eval.py 的 walk_metrics（`--walk`）

实测（第 1~10 章 24289 字 + 打字池 2862 条去重，17001 步，lr 1e-5，落盘 diag/checkpoints_mix25）

  - 小说内部命中 74.3% -> 77.4%（+3.1 点）
  - 小说留出（第 11 章起 2000 字）70.5% -> 73.6%（+3.1 点），top1 40.2% -> 42.3%
  - 前20累计概率 +0.019（对比 5e-4 时的 +0.176）
  - 权重位移 0.054% of std

数据预算

  - 打字池去重后约 2800~2900 步；25% 比例下「各用一遍」可干净匹配约 1.7 万字小说
  - 超出即需复读，而复读会推尖：单次训练的小说量建议 <= 打字池 × 3

未验证

  - **超大数据量下的泛化**：目前最大到 1 万字 / 17001 步，跨到第 11 章仍 +3 点，
    换成别的书、别的文体没有任何数据

已知风险

  - 打字域在大剂量小说训练下仍净负（本次 -2.5 点）：混料能大幅缓解、不能根治，
    长期要靠持续扩充打字池或定期用打字数据回放
  - 打字池复读遍数上升会推高前20累计概率（极化）

对照实验脚本（全部只在显存内跑、跑完还原权重，不动线上头）

  - experiments/ladder_ablation.py   损失打分对象 × 权重方向
  - experiments/lr_sweep.py          学习率扫描（含极化曲线）
  - experiments/mix_ratio.py         混料比例
  - experiments/domain_conflict.py   两个域的梯度夹角
  - experiments/backbone_head_train.py  Base vs Chat 骨干
