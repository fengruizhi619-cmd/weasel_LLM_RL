# 蒸馏实验（第一步：知识能不能迁移）

目标只有一个：**先确认"知识能迁移到循环 Transformer 学生"**。
所以基线臂刻意让等效深度与参数量向教师看齐，把变量压到只剩"架构形状"。

## 文件

| 文件 | 作用 |
|---|---|
| `student_looped.py` | 学生模型：U 个共享 Qwen3DecoderLayer × T 轮循环 + 轮次嵌入 + lm_head（与教师同词表、同宽度、同 GQA/QK-norm） |
| `train_distill.py` | 蒸馏训练：教师 fp16 冻结，学生只训头（冻结主干，与线上在线 RL 同一纪律） |
| `export_typing.py` | 把加密的 `diag/segments.jsonl` / `corpus.jsonl` 解密导出为纯文本（云端不带密钥） |
| `next_sentence_probe.py` | 下一句预测探针：Base 直续写 vs Chat+青简式提示词（5 条件），含跨流取样/语义对照/抄上下文率 |
| `src/` | 数据：小说正文 + 打字语料（`typing.txt`，每行是 `光标前文 + 上屏文本`） |

## 数据

- 小说：银砂纪年第一卷（104,292 字，叙事文）
- 打字：11,483 行 / 625,127 字（技术对话 + 用户实际输入）
- 默认 **打字占 30%**（`--mix-typing 0.3`）；小说尾部 10% 与打字尾部 10% 分别作留出
- 两种混料都该跑一遍：`--mix-typing 0` 与 `0.3`，才能分清"迁移成立"与"专有数据带来的增益"

## 臂（`--arm`）

| 臂 | U | T | 等效深度 | blocks | **唯一参数合计** | 说明 |
|---|---|---|---|---|---|---|
| `stack28` | 28 | 1 | 28 | 440.5 M | **596.1 M** | **不循环对照**：深度=教师、参数=教师（canonical baseline）。权重可从教师逐层继承，`--init pretrained` 开局即 argmax=1.0，用来验证整条通路 |
| `blank28` | 28 | 1 | 28 | 440.5 M | **596.1 M** | **数据充足性对照**：架构与 `stack28` 完全相同，唯一区别是**随机初始化**（不继承教师）。用来回答"是我们的数据不够，还是别的问题" |
| `u4t7` | 4 | 7 | 28 | 62.9 M | **218.5 M** | 循环：同深度、blocks 1/7 |
| `stack4` | 4 | 1 | 4 | 62.9 M | **218.5 M** | 与 `u4t7` 同参数量、不同深度（拆分"深度"与"循环"两个因素） |
| `u1t28` | 1 | 28 | 28 | 15.7 M | **171.3 M** | 循环：极限压缩 |
| `u1t8` | 1 | 8 | 8 | 15.7 M | **171.3 M** | 等效深度 8（此前实测的甜点） |

**参数量口径（踩过坑，务必看）**：`tie_word_embeddings=true`，所以
`embed_tokens.weight`（151936×1024 = **155,582,464**）既是输入嵌入又是输出头。
`parameters()` 对共享参数**只产出一次**，唯一参数量就是它。早先 `param_report()`
在 tie 时又减了一次 embed，把所有"唯一合计"少报了 155.6 M（`blank28` 被报成 440.5 M）。
上面是修好后的真值 —— 关键推论：**`blank28`/`stack28` 与教师等参（596.1 M）**，
而**所有臂在默认 `head` 纪律下可训的都是同一组 155,582,464 个参数**，
所以各臂之间的差异只来自"冻结的那部分主干长什么样"。

## 冻结纪律与 `--train-scope`（第二轮新增）

线上在线 RL 的纪律是**冻结主干、只训头**（tie 时就是只训那份共享嵌入），
所以 `train_distill.py` 默认也是 `--train-scope head`。但随机主干 + 只训头
有个结构性限制，为此加了三个开关：

| 开关 | 作用 |
|---|---|
| `--train-scope head` | 默认。只训头/嵌入（= 线上纪律） |
| `--train-scope last1/last2/last4/last8` | 额外解冻末 N 个唯一层 + final norm（主干 lr 默认 `--lr/10`，可用 `--lr-backbone` 改） |
| `--train-scope layers` | 解冻全部层 + norm（嵌入仍单独一组） |
| `--train-scope all` | 全部参数 |
| `--resume runs/xxx/student.pt` | 从已有学生续训 —— **两步法**："先上课（解冻长跑）→ 再实践（冻结只训头，回到线上纪律）" |

## 初始化（实测结论，很重要）

- **`stack28` + `--init pretrained`**：逐层继承教师，开局 argmax 与教师 **1.0000** → 通路验证臂。
- **循环臂 + `--init pretrained`**：**不要用**。实测 U=4/T=7 开局一致率 0.0000
  （早退曲线 0.125 → 0 → 0 …）。原因：教师第 4 层权重是为"接第 5 层"训练的，
  不是为"再接一次自己"，第二轮起 hidden 就跑到分布外。
  循环臂请用 `--init scratch`（随机初始化后靠蒸馏训起来），这才是真正要回答的问题。

## 冒烟（先跑，约 2 分钟）

```bash
python train_distill.py --arm stack28 --init pretrained --smoke --seq 256 --batch 1 --steps 20
```

## 正式训练

```bash
mkdir -p logs
# 通路验证臂（开局应看到 agree_top1≈1.0）
nohup python train_distill.py --arm stack28 --init pretrained --steps 3000 \
      --seq 256 --batch 4 --micro 1 --out runs/stack28 > logs/stack28.log 2>&1 &

# 循环基线臂（同深度、1/12 参数）
nohup python train_distill.py --arm u4t7 --init scratch --steps 6000 \
      --seq 256 --batch 4 --micro 1 --out runs/u4t7 > logs/u4t7.log 2>&1 &

# 压缩臂
nohup python train_distill.py --arm u1t28 --init scratch --steps 6000 \
      --seq 256 --batch 4 --micro 1 --out runs/u1t28 > logs/u1t28.log 2>&1 &
nohup python train_distill.py --arm u1t8  --init scratch --steps 6000 \
      --seq 256 --batch 4 --micro 1 --out runs/u1t8  > logs/u1t8.log 2>&1 &
```

`--micro` 按显存调：8GB 用 1（会自动梯度累积到 `--batch`）；12GB 可用 2。

## 看什么（metrics.jsonl）

| 字段 | 含义 | 判据 |
|---|---|---|
| `agree_top1` | 学生 argmax 与教师 argmax 一致率 | **迁移是否成立的判据**：能持续上升说明知识搬过去了 |
| `kl` | 与教师的 KL（逐 token） | 与 agree 同向 |
| `student_acc` | 学生 argmax = 真实下一个字 | 任务侧参考（教师自身也可用同一脚本算出） |
| `typing_agree_top1` / `typing_student_acc` | 打字域（专有数据）上的同两项 | **"学生可能超过教师"这条要靠它看** |
| `round_agree` | 第 1..T 轮的早退一致率曲线 | 早退策略依据：第 1 轮就接近第 T 轮 → 默认早退 |

## 第一轮结果（700 步，batch 16，seq 256，打字混比 0.3，教师上限=打字 0.8213／小说 0.3252）

判据是 `typing_agree_top1`（学生 argmax 与教师 argmax 在**打字留出集**上的一致率）。

| 臂 | 初始化 | 小说 acc | 小说 agree | 打字 acc | **打字 agree** |
|---|---|---|---|---|---|
| `stack28` | 继承教师 | 0.5410 | 0.5166 | 0.8096 | **0.8613** |
| `blank28` | **随机** | 0.1938 | 0.2031 | 0.0469 | **0.0488** |
| `u1t8` | 随机 | 0.2671 | 0.2441 | 0.0967 | 0.1025 |
| `u4t7` | 随机 | 0.1748 | 0.2124 | 0.0000 | 0.0000 |
| `u1t28` | 随机 | 0.1494 | 0.1709 | 0.0049 | 0.0078 |

### 结论：不是数据不足

> **口径更正（重要）**：第一轮的「小说」列是在**被污染的留出集**上测的 —— 当时 `build_corpus`
> 先 shuffle 混料、再切 `text[cut:]` 当小说留出，于是那个"小说留出集"是混料尾部，
> 按同样比例掺了打字语料（症状：教师的小说上限会随 `--mix-typing` 变，
> 0.3252 → 0.2510，而教师上限本该是常数）。**打字列是干净的**（打字留出切在混料之前），
> 而结论完全建立在打字列上，所以结论不受影响；第一轮的「小说」列只在同一配比（0.3）的
> 各臂之间可比，不能与别的配比比。已修：留出切在混料之前，小说留出恒为 10,430 字 / 26 窗口。

1. **`blank28` vs `stack28` 是全实验里最干净的对照**：架构相同（28 层真层）、
   参数量相同（596.1 M）、可训参数相同（155,582,464 个共享嵌入）、数据相同、
   步数相同，**唯一差异是冻结主干的初始化**。结果打字一致率 **0.0488 vs 0.8613，差 17 倍**。
2. **同一份数据上教师自己能到 0.8213**，`stack28` 只训头就追到 0.8096（教师的 98.6%）。
   所以数据里含有这个信号 —— **瓶颈不是数据量**。
3. **四个随机初始化臂全卡在同一水平**（打字 acc 0.000 / 0.005 / 0.047 / 0.097，
   小说 acc 0.149 ~ 0.267），**且与参数量无关**：16 M blocks 的 `u1t8` 甚至好于
   440 M blocks 的 `blank28`。小模型早期学得快 —— 这是"大家都还在从零学语言的爬坡段"
   的典型特征，离"学打字域"还很远。
4. **`blank28` 的曲线形状给出了机理**：打字精度在 step 200 见顶（0.105）后一路掉到
   0.049，同时 novel 与打字的 **KL 在 step 100~200 之后一起回升**、而 novel 硬标签精度
   仍在涨。这正是"唯一可训的共享词嵌入在随机冻结主干下只能收敛到**上下文无关的输出偏置**"
   的样子 —— 它学得到词频，学不到上下文条件分布。
   `u4t7`（0.051@150 → 0.000@700）、`u1t8` 同形。

**给产品线的直接含义**：在"冻结主干只训头"这个纪律下，学生**必须继承教师主干**；
"复制一份空白基座再靠我们的数据训头"这条路走不通 —— 再多的打字数据也灌不进去，
因为可训参数只有共享嵌入，它没有可读的中间表示。要走通只有两条：① 继承教师主干
（`stack28`，已验证）；② 先做真正的第一阶段预训练/继续预训练把主干填起来（见下）。

### 第二轮（已跑完第一版、修正口径后重跑）：把"数据不足"这个解释彻底钉死

全部在 `blank28` 臂（同样的 596.1 M、同样的 155,582,464 可训参数），只动三个变量：

| 队列名 | 臂 | 变量 | 想排除的解释 |
|---|---|---|---|
| `b28_pure` | blank28 | `--mix-typing 1.0`（**真·纯打字**，583,556 字） | "打字能力是被 novel 目标挤掉的" |
| `b28_long` | blank28 | 仍是 0.3 混比，2,500 步 | "只是预算不够" |
| `b28_l2` | blank28 | `--train-scope last2` | "随机主干学不出表示" |
| `b28_all` | blank28 | `--train-scope all`，2,000 步 | 第一阶段"上课"到底能走到哪 |
| `b28_2s` | blank28 | `--resume b28_all` + `head`，700 步 | 两步法："上完课再冻结训头"能不能回到线上纪律 |
| `u1t8_all` | u1t8 | `--train-scope all`，2,000 步 | **循环臂**（产品真正想要的形状）能不能靠我们自己的数据训起来 |

赛前预测（写下来，免得事后找补）：若 `b28_pure` 打字一致率仍停在 0.10 附近
→ "被挤掉"不成立，病根是随机主干；若 `b28_l2` 明显跃升 → 表示可学，只是被冻死了。

修口径前跑的那一版 `b28_pure`（当时 `--mix-typing 1.0` 因为 `1-share=0` 除爆，
实际是"小说+全部打字"≈86% 打字，且小说留出被污染）在 step 460 已到
**打字 agree 0.165 / acc 0.157**，是 `blank28` 混比 0.3 那轮早峰 0.105 的 1.6 倍 ——
方向上支持"打字能力被 novel 目标挤掉"，重跑后以干净数字为准。

## 下一句预测探针（`next_sentence_probe.py`）：青简那套提示词对 Chat 模型有效吗

问题：我们手上的 `Qwen3-0.6B-Chat` 能不能**不微调**直接做"下一句预测"。
方法：从加密打字语料折回连续文本流（371 条流，按前 80 字去重），跨流轮转取样 40 条
`(上文 120 字, 下一句 6~20 字)`，五个条件对比：

| 条件 | 首字 | 首3字 | 整句 | LCP均 | 字符F1 | 抄上下文 |
|---|---|---|---|---|---|---|
| `base_greedy`（Base 贪心续写，现线上路子） | **0.300** | **0.200** | 0.000 | **2.40** | **0.226** | 0.050 |
| `chat_plain`（只给上文直接问） | 0.000 | 0.000 | 0.000 | 0.00 | 0.200 | 0.100 |
| `chat_json`（+青简式 JSON 契约） | 0.100 | 0.050 | 0.000 | 0.25 | 0.159 | 0.088 |
| `chat_json_fs`（+2 条 few-shot 示例） | 0.075 | 0.025 | 0.000 | 0.15 | 0.152 | 0.112 |
| `chat_json_loc`（+本地候选，照青简防重复设计） | 0.175 | 0.075 | 0.000 | 1.02 | 0.160 | 0.100 |

**结论：字面命中上这套方法全面不如 Base 直续写，做不到"逐字下一句预测"。**

- Chat 输出的是**语义等价、字面不同**的句子（"检查代码，确保程序运行正常"），
  而输入法要的是**字面等于用户下一个字**，所以首字命中 0.000 ~ 0.175 全部低于 Base 的 0.300。
- **提示词工程救不回来**：加 few-shot 反而**更差**（0.075，还串出日文
  "現在の実験では、超大数据下の…"）。`chat_json_loc` 最好（0.175）是因为把 Base 的
  前两个字当"本地候选"喂了进去，本质是**在吃 Base 的预测**，不是 Chat 自己的贡献。
- **青简的防抄设计并不是万能的**：明确写了"不要把 before 抄进答案"，抄上下文比例
  仍有 8.8% ~ 11.2%（`chat_plain` 10%）。0.6B 的指令跟随不足以稳定守住这条约束。
- 语义相似度**无法**为 Chat 翻案：本域内随机错位配对已达 0.436（上下文尾↔目标 0.489），
  区分度太低；Base 0.552、Chat 各条件 0.495~0.524，只能说 Chat 没有明显更好。

**为什么青简那边成立、搬到这里不成立**：青简的云联想是**整句建议**（用户按 Tab 接受），
不要求字面等于用户本意，而且它有一条本地候选兜底、云端只负责"本地给不出的更好的词"。
搬到"下一句字面预测"这个考核口径上，任务就变了：**这是字符级 continuation 任务，
不是文本生成任务**，RLHF 训出来的"助手人格"在这里是负资产。

**要用就得微调**（把 Chat 的对话人格拆掉、改成续写器），或者**改用途**：
只当"联想建议"给人看，不参与命中率考核。

### 探针的数据坑（都踩过）

- 打字语料里**大量不是句子**：文件路径（`ktop\工作组.md"rs\Feng\`）、数字串、
  英文片段、代码。做"下一句"任务时这些样本天然无解，报告里必须点明。
- **采样偏差**：最早的 `make_cases` 会把 40 条全取自第一条文本流（= 第一篇笔记），
  4 条时 Base 首字 0.75、跨流 40 条时只有 0.30 —— 不跨流轮转取样，结论完全不可推广。
- **重复流**：同一段内容被反复打过，480 条流去重后只剩 371 条。

## 插入式蒸馏（在循环边界插监督信号）

### 动机：嫁接让蒸馏失去意义

嫁接（继承教师主干）把**表示能力**直接送过来了，蒸馏只剩"训头"；而 `blank28` 那组
实验已经证明"随机主干 + 只训头"学到的只是上下文无关的输出偏置。
所以真正要解决的问题是：**怎么让蒸馏重新变成"训练表示"的手段，而不是靠继承权重**。

循环结构天然给了 T 个监督锚点：U=2/T=5（等效深度 10）就有 5 个循环边界。
在每个边界插一个监督信号，同一组共享层就会在 **T 个不同抽象层级**上收到梯度
（D0192 的结论：循环共享改变的是"参数在多个抽象层级被使用"）。
关键推论：**即使主干冻结，hint 监督仍然训得到那份共享嵌入**（h 是"可训嵌入 → 冻结层"
的输出），这正是 `blank28` 缺的那份信号。

### 但"每个边界都插 logit 监督"是错的 —— 这条是测出来的

`probe_depth.py` 测教师每一层用「自己的 final norm + 自己的 lm_head」读出（logit lens）
能预测多准：

| 教师深度 | 1~9 | 10~17 | 18 | 20 | 22 | 24 | 26 | 27 | **28** |
|---|---|---|---|---|---|---|---|---|---|
| 小说留出 top1 | 0.001~0.004 | 0.008~0.036 | 0.057 | 0.123 | 0.185 | 0.248 | 0.315 | 0.363 | **0.401** |
| 打字留出 top1 | 0.000~0.014 | 0.009~0.043 | 0.053 | 0.178 | 0.470 | 0.521 | 0.795 | 0.782 | **0.82** |

**前 20 层几乎不含预测内容（纯建特征），只有最后 8 层在做预测**（两个域一致）。
所以"学生第 t 轮 = 教师第 t·U 层"这个对齐假设对浅臂是错的：
`u1t8` 的 8 个边界会全落在教师的特征构建段（目标读出精度 0.002~0.009），
**把那些 logit 当全权重目标，等于在教学生"早期输出要烂"**。

由此定下实现：

| 监督类型 | 用在哪 | 为什么 |
|---|---|---|
| **表示(hint)** `--ins-hint-w` | 每个循环边界 | 任意深度的 hidden **都是**有信息的表示（即使该层的读出预测不了字）。默认余弦（尺度无关），`--ins-hint-kind mse` 可切 |
| **输出(logit)** `--ins-logit-w` | 只在教师读出 ≥ `--ins-logit-tau` 的深度 | 早层 lens 读出是垃圾目标；tau 过滤用的就是上面这张实测曲线 |
| **最终输出** | 末轮（走原有 KL+CE） | 末轮不许被中间目标稀释，所以末轮不重复计 logit 项 |

深度对齐映射 `--ins-map`：

- `head`：d_t = t·U —— 从头对齐（"学生每 U 层对应教师前 U 层"）
- `tail`：d_t = L − (T−t)·U —— 从尾对齐，把"轮数铺不满深度"的臂（u1t8: T=8 < 28）
  锚在教师的**精修段**（21~28 层），而不是特征构建段。

### 实现要点（都踩过）

- `student.forward(..., collect_hidden=True, grad_rounds={t,...})`：逐轮 hidden **带梯度**
  （很便宜，(B,L,1024)）；逐轮 logits 只对指定轮算**带梯度**版本 —— (B,L,151936) 每轮
  就要几百 MB，`u1t28` 全轮带梯度会吃掉好几 GB。
- 循环边界的 `h` 是**未归一化**的，与教师 `hidden_states[0..L-1]` 同一约定，可直接对齐；
  教师 `hidden_states[L]` **已经是 final norm 后的**，再补一次 norm 就是重复归一化
  （实测 0.401 → 0.284，`probe_depth.py` 里加了自检断言来钉住这条）。
- **hint 损失要按监督点个数取均值**，不是求和：否则 `u1t28`（28 个边界）的总权重是
  `u2t5`（5 个边界）的 5.6 倍，`--ins-hint-w` 在不同臂上就不是同一个超参。
- tau 把监督点全过滤掉时要**告警**，否则命令看着成功、其实没插任何输出级监督。

### 机制验证（本地，u2t5、只训头、80 步）

`ins_cos`（循环边界的 h 与教师同深度 hidden 的余弦均值）从 **0.000 → 0.050**，
首轮 0.004→0.071，末轮 −0.003→0.046，loss 25.1→14.0：
**随机 2 层块确实在被推向教师 5 个深度的表示**，机制接通了。

### 但 80 步的配对对照里，插入式**更慢**（诚实记录）

同为 u2t5 / 只训头 / 80 步 / batch 2：

| | 插（hint-w 1.0，head 映射） | 不插 |
|---|---|---|
| novel agree@80 | 0.0469 | **0.0859** |
| novel acc@80 | 0.0273 | **0.0449** |
| loss@80 | 14.04 | 9.11 |
| 小说早退曲线 | 0.064 0.061 0.055 0.042 0.031（递减） | 0.089 0.098 0.098 0.093 0.078（**拱形**） |

解释：这一版用的是 `head` 映射，5 个边界全落在教师特征构建段（lens 精度 0.002~0.029），
用一个"不含预测内容"的方向去拉随机主干下的共享嵌入，80 步预算里就是白干。
这正是 `tail` 映射存在的理由。**这个数只说明"head 映射 + 极短预算"不行，不代表机制不行。**

## 这条路走到哪了：已证的死路 vs 没测过的正题

### 已经确证走不通的（不要再试）

1. **空白基座 + 冻结主干只训头**：`blank28` 打字一致率 0.0488 vs `stack28` 0.8613（差 17 倍），
   机理已定位 —— 唯一可训参数是共享词嵌入，它只能学到上下文无关的输出偏置。
   `b28_pure`（真·纯打字数据、同样只训头）把它测得更精确：step 2100 打字
   agree **0.1729** / acc **0.1650**，是混比 0.3 那轮的 3.5 倍 —— 说明混料确实在拖累打字域，
   但 0.165 仍只有教师的 **21%**，瓶颈依然是主干而不是数据。
2. **嫁接之后再谈"蒸馏"**：那就是训头。嫁接把表示能力直接送来了，蒸馏这一步没有内容。
3. **Chat 模型 + 提示词做逐字下一句预测**：首字命中 0.000~0.175，全面低于 Base 的 0.300。

### 但第一轮实验**没有测过正题**

第一轮的 scratch 循环臂不是在测"折叠"，是在测"**用 700 步从零学会语言**"：
700 步 × batch 16 × seq 256 = **2.87M** 个 token 位置，而教师的预训练量级比这高
5~6 个数量级。那是必输的测法，胜负与"折叠可不可行"无关。

**折叠是另一个问题**：学生不需要学会语言，只需要学会"**第 t 轮复现教师第 d_t 层的那一步**"
—— 教师其余 27 层已经给出了目标。两者需要的数据量根本不是一个量级。

补上折叠必需的三个件（本轮补齐）：

| 缺什么 | 为什么必需 | 状态 |
|---|---|---|
| **逐轮监督**（插入式） | 只有最终输出被监督时，中间轮次没有任何约束，共享块无从知道"这一轮该干哪一层的话" | 已建 |
| **关系(相似度结构)监督** `--ins-rel-w` | 逐点余弦只约束每个 token 的方向，管不到 token 之间；而折叠要迁移的正是**计算模式**。用 `softmax(h hᵀ)` 归一化后的相似度矩阵对齐，零额外教师开销 | 本轮新增 |
| **非均匀深度分配** `--ins-depths` | 教师前 20 层建特征、后 8 层做预测（实测），均匀铺深度等于逼每轮做性质不同的 3 层活；显式深度表让浅层大步、深层小步 | 本轮新增 |

### 文献里这件事有名字和成功先例（诚实标注，不是我们发明的）

- **MiniLM / 深层自注意力蒸馏**（Wang 2020）：学生模仿教师的**自注意力分布**与
  **value 关系矩阵**，12→6 层保住约 99% 性能 —— 正是"折深度"这条路，
  而且它的核心手段就是**中间关系监督**（我们刚补上的那一件）。
- **BERT-of-Theseus**：逐层替换 + 蒸馏；**RKD / FSP 矩阵**（Yim 2017）：相似度结构蒸馏。
- **Universal Transformer / 循环深度**：U 层 × T 轮的架构承诺。

我们要做的组合（循环折叠 + 逐轮 logit-lens 目标 + 关系监督 + 非均匀深度表）
文献里没有现成答案，但每一块都有先例。

### 真正的风险（要盯着这一条）

折叠 28 层到 8~9 轮，要求**一个共享块**同时当好"建特征的层"和"做预测的层"——
教师的这些层是异质的（第 2 层和第 26 层干的事完全不同）。如果共享块表达不了这种异质性，
折叠就是有损的、且不可修。**这条是可测的**：看 `ins_cos` / `ins_rel` 在每个边界能压到多低。
早边界压不下去，就只能折精修段（但保留前 20 层冻结前缀 = 28 层前向没少跑，**没有算力收益**，
所以那不是出路）。

### 队列 3「折叠」（等队列 2 结束后自动开跑）

全部 `--init scratch --train-scope all --steps 3000`（给折叠一个真正的机会，而不是 700 步）：

| 队列名 | 臂 | 监督 | 想回答 |
|---|---|---|---|
| `f_u1t8_off` | u1t8 | 无中间监督 | 朴素折叠（= 第一轮做法但跑够步数） |
| `f_u1t8_uni` | u1t8 | hint，尾对齐 21~28 | 插入式监督对折叠有没有用 |
| `f_u1t8_uni_rel` | u1t8 | hint + 关系 | 关系监督的增量 |
| `f_u1t9_nonuni` | u1t9 | hint，深度表 4,8,12,16,20,22,24,26,28 | **非均匀折叠** |
| `f_u1t9_nonuni_rel` | u1t9 | hint + 关系 + 非均匀 | 两项叠加 |

**赛前预测**：① `nonuni` > `uni`（若不然，"教师深度分配不均"对监督点设计就没有指导意义，
我的推论被证伪）；② `uni` > `off`（插入式监督对折叠有效，本轮最重要的一条）；
③ `_rel` > 非 rel；④ **全部仍远低于 `stack28` 的 0.86** —— 3000 步内不可能追平继承，
这一轮只看**方向**，不看追平。

## 「数据不够」这个解释站不站得住：欠拟合 vs 过拟合

**判据只有一条**：模型能不能拟合**自己的训练数据**。

| 症状 | 诊断 | 加数据有用吗 |
|---|---|---|
| 训练集高、留出集低 | 过拟合 | **可能有用** |
| 训练集也低、且远离教师 | **欠拟合** | **没用** —— 只能改函数类/目标/初始化 |

实测（`b28_pure`，纯打字数据、只训头、step 2120）：

| | 学生 | 教师（同一批输入） |
|---|---|---|
| 训练窗口 acc | **0.3394** | 0.82 |
| 打字留出 acc | **0.1650** | 0.8213 |

两边都远离教师 → **欠拟合**。模型在自己的训练数据上只打到 0.34，而教师在同一批输入上
0.82 —— 这不是"没见过足够的样本"，是"**可学的函数类里没有这个答案**"
（随机主干冻结后唯一可训的是共享词嵌入，它只能表达上下文无关的输出偏置）。
**所以数据量不是当前的瓶颈；我们已经把"数据够不够"这件事测过了，答案是够。**

### 要分清"学什么"，三件事的数据需求差 6 个数量级

| 要学什么 | 数据需求 | 我们的情况 |
|---|---|---|
| **语言**（从零预训练） | ~10¹² token 量级 | 我们 730k 字 ≈ 0.5M token，**差 6 个数量级 → 确实没戏** |
| **教师在这批输入上的输出**（蒸馏） | 只需输入的**覆盖**，能力来自教师 | **实测已证可行**：`stack28` 用我们的数据训头，打字域复现教师的 **98.6%**（0.8096 / 0.8213） |
| **第 t 轮复现教师第 d 层**（折叠） | 监督对 = 训练 token 位置 × 边界数 ≈ 62 万/epoch，3000 步到 10⁹ 量级；且标签由教师现算 | 覆盖问题，不是"能力涌现"问题 |

**"数据不够"只杀死第一条路 —— 而第一条恰恰是我们不需要走的那条**（战略是借涌现，能力从
教师借来，我们只做结构重组）。**把三件事混成一件，就会从"欠拟合"错误地推出"只能放弃"。**

### 真正的数据相关限制（诚实列出）

1. **域覆盖**：语料是「一个人的技术笔记 + 一部小说」。蒸馏出的学生在**这个域内**可以逼近
   教师，**域外不行**。这是**范围**限制，不是"蒸不出能力"。
2. **评测集小**：打字留出 99 窗口 / 4.2 万字，小说留出 26 窗口。小差异不可信 ——
   同一个小说留出集，教师上限被不同窗口数测出过 **0.3252 / 0.4014 / 0.4287**。

### 已修的测量 bug（口径不可比）

`teacher_acc` 早先默认 `max_batches=4`（batch 1），而学生评测走的是 `evaluate(max_batches=8)`
—— **"上限"与"学生"根本不在同一批输入上**，"差距"列因此不可信。
现在两边统一用 `--eval-batches`（默认 16，`<=0` 用满留出集），并在每轮评测后自动打印判定行：

```
[判定] 训练acc=… （教师 …，差距 …）｜ 留出acc=…（差距 …）→ 欠拟合/过拟合
```

口径变更的**可比性说明**：窗口是按前缀取的（`x[0:nb]`），所以旧跑（4/8 窗口）用的是新跑
（16 窗口）的**前缀子集** —— 可比，只是更抖。第一轮/第二轮的所有数字都出在旧口径上。

## 已修的坑（都踩过，别再犯）

1. `Qwen3DecoderLayer.forward` 返回**裸 tensor**，写 `[0]` 会切掉批次维；B=1 时后面的广播会把它"修"回三维，于是单层正常、多层在第二层炸。
2. cos/sin 传 **3 维** `(B,L,head_dim)`：`apply_rotary_pos_emb` 内部会 `unsqueeze(1)`，自己再补一次就变 5 维。
3. 不要给层传 `attention_mask`：torch 2.5.1 下 `use_gqa_in_sdpa` 要求 mask is None 才启用 GQA 内核；等长序列本来不需要。
4. **final norm 只能施加一次**：`Qwen3Model` 输出已是归一化后的，写 `lm_head(self.norm(h))` 就是重复归一化（表现：分布看着正常、argmax 只对 0.48）。
5. 教师键名带 `model.` 前缀（`model.embed_tokens.weight` / `model.norm.weight`），不补前缀会静默漏掉嵌入与 final norm。
6. `self.apply(_init_weights)` 会覆盖 `round_emb` 的零初始化（实测变成 0.064）→ 必须在 apply 之后再重置一次。
7. 学生必须与教师**同词表同宽度**：换宽度/换词表后嵌入与头形状不符，权重无法继承，"等效参数"的前提就没了。
8. **tie 模型的唯一参数量别自己减 embed**：`parameters()` 对共享参数只产出一次（`_named_members` 默认 `remove_duplicate=True`），再减一次就把 155.6 M 少报了。`blank28` 曾因此被报成 440.5 M（真值 596.1 M）。
9. **评测取样必须跨流轮转**：`make_cases` 早期实现按流顺序填满额度，40 条全部来自第一篇笔记，把 Base 首字命中从 0.30 虚高到 0.75。
10. **Qwen3-Chat 默认开思考模式**：不显式 `enable_thinking=False`，`max_new` 会被 `<think>` 吃光，四个条件的输出全变成思考片段（首字命中全 0，看着像"模型完全不行"）。
11. **给模型看"本地候选"绝不能掺目标字符**：早先写成 `tgt[:2]` 当本地候选 = 直接把答案喂进去。正确做法是用本地模型自己的预测（这里是 Base 的前两个字）。
12. **JSON 回复会被 `max_new` 截断**：`json.loads` 失败后必须有正则兜底（残缺 JSON 没有收尾引号），否则预测被解析成 `sentence": "…` 这种噪声。
13. **看 emoji/中文日志时别用 `2>&1 |`**：PowerShell 会把 native stderr 的 tensorflow 警告包成 `NativeCommandError`，让脚本"看起来"退出码 1；实际 `rc=0`。要判退出码就重定向到文件单独看。
14. **留出集必须切在混料之前**：先 shuffle 混料再取 `text[cut:]`，那个"小说留出集"就是混料尾部，会按比例掺进打字语料。识别症状：教师自己在"小说留出集"上的 top1 随 `--mix-typing` 变（0.3252 → 0.2510），而它本该是常数。
15. **`--mix-typing 1.0` 会除爆**：`want_typ = len(novel) * share / (1 - share)`，share=1 时分母为 0（被 `max(1e-9, …)` 兜成 1e14），于是"纯打字"实际跑成"小说 + 全部打字"。`share >= 0.95` 要显式短路成"只用打字"。
16. **`pkill -f <脚本名>` 会杀掉自己**：paramiko 用 `bash -c "<内容>"` 执行，那条命令行里就含脚本名，`pkill -f` 一匹配就把执行中的 shell 杀了（症状：脚本没有任何输出、后半段没执行）。用 `ps | grep '[t]rain' | awk '{print $2}'` 取 PID 再 `kill`；后台起长任务用 `setsid nohup … < /dev/null &`，否则 ssh 通道会被抱住、客户端读超时。
17. **`hidden_states[L]` 已经是 post-norm**：transformers 的约定是 `[0..L-1]` 为各层未归一化输出、`[L]` 过完 final norm。给 `[L]` 再补一次 `model.norm` 就是重复归一化（实测教师最终层 top1 从 0.401 掉到 0.284）。**做逐层读出时一定要加自检**：`[L]` 的 lens 必须与 `teacher(x).logits` 逐位一致。
18. **`make_windows` 的 y 已经右移过**：`logits[j]` 直接对 `y[j]`，再切 `[:, :-1]` 会 510 vs 512 不对齐。
19. **多段损失要按监督点取均值**：求和会让不同 T 的臂拿到不同总权重，超参就不可比了。
20. **别覆盖正在跑的队列会重读的代码**：bash 队列每个臂都重新启动 python、重新读脚本，中途改文件会让同一次实验的不同臂跑在两版代码上。要改就另开一个目录（`/root/distill_ins` 用软链指回 `model/` 与 `src/`），两套队列互不干扰。
21. **传多行命令给 paramiko 要用 `@本地文件`**：PowerShell 会把多行字符串按换行拆成多个 argv（症状：`invalid literal for int() with base 10: '$f'`）。`_cloud_run.py` 支持 `@文件` 把整份脚本内容当命令。
22. **"上限"与"学生"必须同批窗口**：`teacher_acc` 默认 4 个窗口、学生评测 8 个，两边减出来的"差距"是拿两批不同输入相减。同一个留出集因此测出过 0.3252 / 0.4014 / 0.4287 三个教师上限。现在统一 `--eval-batches`，且窗口按前缀取 → 旧口径是新口径的前缀子集，可比但更抖。
23. **`git commit -m` 里带 ASCII 双引号会被 PowerShell 拆参**：症状是 `error: pathspec 'logit' did not match any file(s)`。把提交信息写进文件、用 `git commit -F 文件`。
24. **别在 bash 队列运行中改它的脚本文件**：bash 是增量读取运行中的脚本的，改字节可能让后续命令错位。要加内容就另写一个脚本 + 用完成标记（`grep -q ALL_xxx_DONE`）串起来。
